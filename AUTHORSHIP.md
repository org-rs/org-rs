# Authorship and LLM assistance

## Disclosure

Some of the code currently in this repository was written with assistance
from large language models (LLMs).  This document exists to state that fact
plainly, rather than to conceal it.

This assistance was used as a **prototyping aid**: a way to explore the shape
of the parser quickly.  It was never intended to be the final authorship of
the project.

## Where LLM-assisted code is allowed

LLM-assisted code **may live in feature branches** during development.  The
line this project draws is at the **official release**, not at the merge:

> No official (tagged) release of `org-rs` will contain LLM-generated code.

Per the Free Software Foundation's guidance on generative tools, any
LLM-generated material in a feature branch is present **only temporarily**.
Before such code becomes part of a release, its design and logic are to be
reclaimed by a human — either replaced outright or genuinely re-derived and
re-authored from the reference implementation and the project's own tests.
Feature branches are a workshop; releases are the finished work, and the
finished work is human-authored.

To be explicit about the goal: this is **not** an effort to make LLM-generated
code *look* human-written.  That would defeat the purpose.  The goal is the
opposite — to identify LLM-originated code and re-author it so that the
creative authorship is, in fact, human, before it ships.

## Why this matters

### 1. Copyright

Copyright protection requires human authorship.  Purely machine-generated
output, produced without human creative control, is generally held not to be
copyrightable (see, e.g., the U.S. Copyright Office's guidance on works
containing material generated by artificial intelligence, 2023, and the
long-standing human-authorship requirement in copyright law).

This is a particular problem for a GPL-licensed project.  The GNU General
Public License is a *copyleft* license: its guarantees are enforced **through**
copyright.  Code that cannot be copyrighted, or whose authorship and provenance
are unclear, weakens the license that protects every downstream user's freedom.
The FSF has publicly raised these concerns about generative code assistants
(see the FSF's funded call for white papers on the legal and philosophical
questions around GitHub Copilot, 2021).  A copyleft *release* therefore cannot
responsibly contain LLM-generated code — hence the boundary above: such code is
confined to feature branches during development and must be human-authored
before it reaches a release.

### 2. Ethics — no misrepresentation

Beyond the legal question, presenting LLM-generated code as if it were entirely
human-written would be dishonest.  It would misrepresent the provenance of the
work to reviewers, to contributors, and to downstream users who rely on a clear
chain of authorship.  This project chooses to disclose LLM assistance openly
instead of hiding it.

## Current limitations of the record

Honesty requires one further admission: **not every commit that contains
LLM-generated or LLM-assisted code carries a clear marker to that effect.**
During prototyping, some LLM-assisted changes were committed to feature
branches without a notice in the commit message or the code identifying them as
such.  The branch history is therefore not a complete or reliable index of
which code was machine-assisted.

What can be said is that the code, as it stands, **works** — it builds and
passes the test suite.  Its correctness is not in question here; only its
authorship and its eligibility for an official release are.  Re-authoring this
code by hand does not change what it does; it changes *who wrote it*, which is
the point.

## In short

- Some code here was drafted with LLM assistance.
- LLM-assisted code may live in feature branches, but **no official release
  will contain LLM-generated code** — per FSF guidance, that state is temporary.
- LLM-generated code raises real copyright problems, especially for copyleft.
- Passing it off as human-written would be unethical, so we disclose it here.
- The branch history does not mark every such change, but the code is working
  and will be re-authored by a human before it ships in a release.
